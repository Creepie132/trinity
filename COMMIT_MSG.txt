fix(i18n): sync language across Web and PWA via DB as source of truth

Problem: User changes language in Web, opens PWA on same device/account
and sees the old language. Cause: Web and PWA have isolated localStorage
and cookie jars. The previous architecture used cookie+localStorage as
primary sources, so changes never propagated between the two clients.

Fix: DB is now the source of truth for language (same pattern as landing
page preference). Priority chain:
  1. org_users.preferred_language — DB truth, read at SSR
  2. trinity_locale cookie — fast fallback when DB unreachable or no auth
  3. 'he' default

Root layout now calls getUserPreferences() on every SSR render. When DB
returns a language different from the cookie, cookie is rewritten so the
next SSR is fast. localStorage is synced with SSR value on LanguageProvider
mount, so Web and PWA (and any number of devices) converge to DB.

Removed the `<head>` flash-prevention script that read localStorage and
force-switched lang/dir. That script was the thing actively breaking the
sync — it would override SSR's correct lang with whatever stale value
localStorage held on that specific client.

Write path (LanguageContext.setLanguage) already writes to DB, cookie, and
localStorage — unchanged. Only the read path was broken.
