fix(pwa): add /pwa-start entry that honors user's landing preference

Problem: PWA manifest had start_url="/dashboard". When user tapped the
PWA icon, the app opened directly at /dashboard, completely bypassing
/callback and the redirect logic added for the landing-page feature.
The user's default_landing_page preference was ignored only in PWA.

Why /callback-based fix wasn't enough:
  - /callback only runs during OAuth code exchange
  - A returning PWA user has a valid session cookie already, no callback
  - The browser just navigates straight to start_url

Why not redirect from /dashboard itself:
  - Manual clicks on "Dashboard" in the nav would also redirect
  - Would create an infinite loop or require a query-param hack

Solution: dedicated entry point /pwa-start
  1. Check auth via cookies-based supabase client
  2. Not logged in → /login
  3. Logged in → read user_nav_preferences.default_landing_page
  4. Redirect to resolved path (fallback /dashboard on any error)
  5. manifest.json: start_url changed to /pwa-start

The page is force-dynamic + nodejs runtime so every PWA open evaluates
the current preference fresh — no edge caching of the redirect.

IMPORTANT for Vlad: your already-installed PWA may cache the old
manifest with start_url=/dashboard. Browsers aggressively cache
manifest.json. To pick up the new start_url:
  - Chrome Android: PWA icon → Long press → App info → clear data,
    OR remove icon and re-add to home screen
  - Vercel build-id changes will eventually invalidate SW, which
    should re-fetch manifest, but this can take a full SW cycle.
